## 1. 게임 루프 요약

```
game start: day=1, hearts=5, swaps=5, 보드 36칸 무작위 → 자동 매치 해소
repeat:
  [낮/계획] 스왑이 0이 될 때까지 보드 행동(각 1 스왑)
            + 무료 행동(상자 열기, 대포 방향 전환, TNT, 요정)
            스왑은 매치-4 이상, 콤보, 상자로 추가 획득
  [밤/공격] 웨이브 생성 → 드래곤이 아래에서 위(성)로 비행 → 타워 자동 사격
            성에 도달한 드래곤 1마리당 하트 -1. 하트 0이면 게임 오버(부활 없음)
  [전환]   드래곤·투사체가 모두 사라지면 day += 1, 스왑 = 5로 리셋
score = (게임 오버 시점의 day) + 1000 × min(5, floor((day-1)/10))
```

핵심 성질:

- **하루는 스왑을 모두 써야 끝난다.** 일찍 끝내는 버튼은 없다(휴식일 제외, §13). 남은 스왑은 다음 날로 넘어가지 않는다. 다음 날 시작 시 5로 **재설정**된다. ✅
- 따라서 하루의 길이(행동 수)는 가변이다. 금상자를 열면 +380 스왑이 되어 그날 380번 이상 행동하게 된다.
- 원본에서 밤에 할 수 있는 조작은 대포 방향 전환과 요정 사용뿐이다(§5.8). 시뮬레이터는 이 둘을 끄는 단순화를 쓴다. 따라서 **시뮬레이터에서는** 의사결정이 모두 낮에 일어난다.

## 2. 보드와 좌표계 ✅

- 열 x = 1..6 (왼쪽→오른쪽), 행 y = 1..7 (위→아래). 격자 전체는 6×7이다.
- First 레벨 지형: y = 1..6은 땅(grass), y = 7은 물(water). 타일이 놓이는 칸은 36개다.
- **y = 1이 성(castle)과 맞닿은 윗줄**이다. 드래곤은 아래쪽 화면 밖(y ≥ 10)에서 나타나 y가 작아지는 방향(위)으로 날아간다.
- y = 0은 성이다. 성 포탑 슬롯은 (1,0)과 (6,0) 두 곳이다(§5.5).
- 보드 밖 칸의 판정(`dk`):
  - x < 1, x > 6, 또는 y ≥ 8 → 물. 타일을 이쪽으로 끌면 **버리기(toss)** 가 된다.
  - 1 ≤ x ≤ 6이고 y ≤ 0 → 성(땅 취급). 이쪽으로는 버릴 수 없다.
- 지형 종류: `grass`(땅), `water`(물), `road`(Road/Lanes 레벨), `cannon slot`(대포 전용 칸).
- 픽셀 좌표: 타일 한 변은 48px이다. 타일 (x,y)의 좌상단은 ((x-1)·48, (y-1)·48)이다. 드래곤과 투사체 좌표는 중심점이다.
- 시간 단위는 **프레임(1/60초)** 이다. 로직은 프레임 단위로 진행된다. 2배속 모드는 초당 로직 프레임 수만 늘리므로 프레임당 규칙은 같다. ✅

## 4. 자원 생성(스폰)과 중력 ✅

### 4.1 무엇이 생성되나

- 새 타일은 자원 5종 중 **균등 확률(각 20%)** 로 뽑힌다(`kindSetRandomly`, 보드 RNG `V`).
  - 구현은 18종 전체 목록에서 균등 추출한 뒤 자원이 아니면 다시 뽑는 방식이다. 결과 분포는 균등하다. 정확한 재현 방법은 부록 A 참고.
  - Poor 레벨은 Treasure를 제외한다(각 25%).
- 예외: 돌을 성에 넣어 생긴 빈자리의 새 타일은 **Stone이 아닌 것**으로 다시 뽑는다(`removeDeleteAndReplace(true)`).
- 생성 시 "매치가 생기지 않게 하는" 보정은 없다. 새 타일로 매치가 생기면 자동으로 연쇄 해소된다.

### 4.2 중력 (`removeFromGrid`)

타일이 (x,y)에서 제거되면 다음 순서로 처리한다.

0. **제거된 칸 자체가 물이거나 cannon slot이면 여기서 끝난다.** 위 타일은 내려오지 않고 새 타일도 생성하지 않는다. 빈 슬롯이나 빈 물 칸이 남고, 난수도 쓰지 않는다. ✅🔁
1. 같은 열에서 그 위에 있는 타일(y-1, y-2, …, 1)을 한 칸씩 아래로 내린다.
2. 위로 올라가다 물이나 cannon slot을 만나면 거기서 멈추고, 새 타일은 생성하지 않는다(구멍이 남는다).
3. 위로 올라가다 빈칸을 만나면 멈춘다. 그 빈칸이 y = 1이었을 때만 생성한다.
4. 1행까지 모두 내렸으면 (x,1)에 새 무작위 자원을 1개 생성한다. 단, 휴식일(§13)에는 생성하지 않는다.

- 제거 1회당 해당 열 맨 위에 정확히 1개가 생성되는 것은 **휴식일이 아니고, 제거 칸이 일반 땅이며, 그 위 경로에 물·슬롯·빈칸이 없을 때**뿐이다.
- First에서도 예외가 생긴다.
  - 악마 거래로 생긴 cannon slot의 대포가 제거되면 슬롯이 빈 채로 남고, 바로 위 타일도 움직이지 않는다.
  - 7행(물)의 빙산이 제거되면 아무것도 생성되지 않는다.
  - 휴식일의 제거는 열 위쪽에 구멍을 남긴다.
- 여러 타일을 한꺼번에 제거할 때는 **행 우선(y=1→7, 각 행에서 x=1→6) 순서**로 하나씩 제거한다. 새 타일은 제거할 때마다 즉시 생성된다(RNG 소비 순서).

### 4.3 초기 보드와 매일 아침 보충

- 새 게임: 땅 36칸을 행 우선 순서로 무작위 채운다. 이후 자동 매치 해소(§6)가 돌아서, 처음부터 타워가 생길 수 있다. 첫 플레이 튜토리얼용 고정 배치는 무시한다.
- 게임 시작과 매일 아침의 자동 해소에도 큰 매치·콤보 보너스(§7)가 붙는다. 그래서 1일차 시작 스왑은 시드에 따라 5보다 많을 수 있다(원본에서 5~9 관측). ✅🔁
- 매일 시작(`m4`): 각 열의 위에서부터 첫 막힌 칸(물·점유·슬롯) 위쪽 빈칸을 채운다. 보통의 First 보드에는 빈칸이 없다. 휴식일 다음 날 구멍을 메울 때 쓰인다.

## 5. 낮(계획) 단계의 행동

### 5.0 스왑 예산 ✅

- 매일 시작 시 `swaps = 5`로 재설정한다(누적 아님).
- 보드 행동(§5.2–5.6)은 **1 스왑**을 쓴다. 스왑은 행동 직후, 매치 해소 **전에** 차감된다.
- 해소가 끝난 뒤 `swaps ≤ 0`이면 보드 행동은 더 할 수 없다. 그래도 밤이 시작되기 전까지는 무료 행동(§5.7: 상자 열기, TNT, 요정, 대포 방향 전환)을 할 수 있다. ✅👤
  - 상자를 열어 스왑을 얻으면 낮이 이어진다(👤 확인).
  - 원본 기본 동작은 스왑이 0이 된 뒤 30프레임이 지나면 웨이브가 시작된다(그 사이에 탭 가능). 설정 `safemodedayend`를 켜면 확인을 기다린다. ✅
  - 시뮬레이터 규칙은 이 설정을 켠 상태와 같다: 스왑이 0이면 행동 선택지는 "무료 행동" 또는 "밤 시작"이다. 할 수 있는 무료 행동이 없으면 곧바로 밤으로 넘어간다.
- 무료 행동(§5.7)은 스왑을 쓰지 않는다.

### 5.1 드래그 행동의 공통 형식과 전처리 ✅🔁

행동은 (타일 A의 좌표, 방향 d ∈ {상, 하, 좌, 우})로 정한다. A는 보드 안(**7행 포함**)의 움직일 수 있는 타일이고, B는 A의 인접 칸이다.

판정 전에 목적지를 전처리한다(`$C`, `d9`).

1. **모루 우선**: B가 A를 받을 수 있는 모루(§5.6 조건)이면 목적지 타일을 비운 것으로 두고, §5.3의 모루 분기로 간다.
2. 아니면 B의 타일을 목적지 타일로 삼는다. 단, **A와 B 중 한쪽만 빙산이면 목적지를 "빈 것"으로 취급한다.**
3. 2번에서 목적지를 비웠는데 B가 모루인 경우는 무효다.
4. 목적지 타일이 있으면 §5.2, 없으면(빈 칸·보드 밖·위에서 비운 경우) §5.3으로 판정한다(`dR`).

결과적으로 다음이 성립한다(원본 재현 🔁).

- 일반 타일을 7행 물 칸의 빙산 쪽으로 끌면 **버리기**가 된다(§5.3 d). 빙산은 그대로 남는다.
- 빙산을 땅 위 타일 쪽으로 끌면 무효다.

### 5.2 B에 타일이 있는 경우: 스왑 ✅

- 유효 조건(`gq`), 모두 만족해야 한다.
  - A와 B가 **완전히 같은 타일(같은 종류이면서 같은 tier)이 아닐 것**. 종류가 다르거나 tier가 다르면 된다.
  - 빙산은 빙산끼리만, 빙산이 아닌 타일은 빙산이 아닌 타일끼리만 교환한다. 한쪽만 빙산인 경우는 §5.1 전처리에서 이미 §5.3으로 넘어가므로 여기까지 오지 않는다.
  - A나 B가 cannon slot 위에 있으면, 둘 다 대포일 때만 교환한다.
- 결과: 두 타일의 위치를 바꾼다. 1 스왑을 쓰고, 이어서 매치 해소(§6)를 한다.
- **매치가 생기지 않아도 스왑은 성립한다**(일반 match-3 게임과 다름).
- A를 받을 수 있는 모루는 §5.1에서 모루 사용으로 처리된다. 조건이 맞지 않는 모루와는 일반 스왑이다.
- 7행 빙산끼리도 등급이 다르면 교환된다. 🔁
- 유효하지 않으면 아무 일도 없고, 스왑도 쓰지 않는다.

### 5.3 B가 비어 있거나 보드 밖인 경우

위에서부터 차례로 판정한다.

| 순서 | 조건 | 결과 | 비용 |
|---|---|---|---|
| a | A가 Stone, A가 y=1, 방향이 위, hearts < 36, 휴식일 아님 | 성 보수 (§5.4) | 1 |
| b | A가 Arrow tower, A가 (1,1) 또는 (6,1), 방향이 위, 포탑 조건 만족 | 성 포탑 장착 (§5.5) | 1 |
| c | §5.1에서 모루로 판정됨 | 모루 사용 (§5.6) | 1 |
| d | B가 땅이 아님(물이거나 좌·우·아래 보드 밖). 7행 물 칸의 빙산 쪽도 포함 | **버리기(toss)**: A 제거, 중력(§4.2), 생성 | 1 |
| e | B가 보드 안의 빈 땅(빙산이면 빈 물 칸) | A를 B로 옮긴 뒤 아래가 빈 땅인 동안 낙하 | 1 |
| – | 그 밖(위쪽 성 방향인데 a·b 조건 불충족, 빙산 → 땅 타일 등) | 무효 | 0 |

- 빙산은 d에서 "보드 밖"일 때만 버려지고, e에서는 빈 물 칸으로만 이동한다.
- First 보드에서 버리기가 가능한 경우: x=1에서 왼쪽, x=6에서 오른쪽, y=6에서 아래(물. 빙산이 있어도 됨). 7행 빙산은 좌·우·아래 보드 밖으로 버린다. 🔁
- e에서 옮긴 칸이 cannon slot이면 대포만 들어갈 수 있다.
- 앱은 일정 tier 이상을 버릴 때 확인 창을 띄운다. 이것은 UI일 뿐이므로 시뮬레이터는 무시한다.

### 5.4 성 보수 (Stone → 성) ✅

- 1행의 Stone을 위로 끌면 hearts +1이 된다(최대 36).
- 돌은 제거되고, 그 열에는 **Stone이 아닌** 새 타일이 생성된다.
- 휴식일(§13)에는 불가능하다.

### 5.5 성 포탑 장착 ✅

- 포탑 슬롯은 성의 x=1, x=6 두 곳이다(`iu[1]`, `iu[6]`, 좌표 (x,0)).
- (1,1) 또는 (6,1)에 있는 Arrow tower를 위로 끌면 그 열의 포탑 슬롯으로 들어간다. 조건은 **슬롯이 비었거나 기존 포탑의 tier < A의 tier**인 것이다. 기존 포탑은 사라진다.
- A가 있던 칸은 중력과 생성으로 채워진다.
- 포탑 Arrow tower의 사거리는 **±2(5×5)** 로 일반(±1)보다 넓다. 포탑은 밤에만 사격한다(§9.5).

### 5.6 모루(Anvil) ✅

- 조건: 타일 A를 인접한 모루 N 쪽으로 끌 때 다음을 모두 만족해야 한다.
  - N.tier == A.tier + 1
  - A가 업그레이드 가능할 것(상위 버전이 있고 tier < 4)
  - A가 모루가 아닐 것
- 결과: A가 N 자리로 이동하고, A의 원래 칸은 중력과 생성으로 채워진다. 모루는 사라지고 A는 tier+1이 된다(자원이면 대응 방어물 T1). 1 스왑을 쓰고 이어서 매치 해소를 한다.
  - A가 N 자리에 놓일 수 없으면(예: 빙산을 땅 위 모루로) 모루만 중력과 함께 제거되고, A는 제자리에서 업그레이드된다.
  - **모루가 A 바로 위에 있으면**, A를 빼는 중력으로 모루와 그 위 타일들이 한 칸씩 내려오고 맨 위에 새 타일이 생긴다. A는 모루가 *내려온* 칸에 놓이고 모루는 사라진다. 🔁
- 모루 tier별 용도: T1 = 자원→T1, T2 = T1→Bronze, T3 = Bronze→Silver, T4 = Silver→Gold. 상자, 요정 같은 업그레이드 가능 타일에도 쓸 수 있다.
- 조건이 맞지 않는 모루로 끌면 일반 스왑이 된다.
- 같은 tier 모루 3개가 매치되면 tier+1 모루가 된다.

### 5.7 무료 행동(탭) ✅

| 대상 | 가능 시점 | 효과 |
|---|---|---|
| Chest | 낮 동안 언제나. 스왑이 0이어도 밤 시작 전이면 가능 | 상자 열기 (§7.3, §8) |
| Cannon | **언제나(밤 포함)** | 선호 방향(좌/우) 토글 (§9.5) |
| TNT | 낮 동안 언제나(스왑 0 포함) | "전부 폭파"(보드의 모든 T0 자원 제거) 또는 "하나 폭파"(tier 0 타일 1개. 자기 자신 제외). 충전 1 소모, 0이 되면 TNT 제거. 이후 중력, 생성, 연쇄 |
| Fairy / Fairy House | 낮 동안 언제나(스왑 0 포함), **밤에도 가능** | 타일 A를 집어 (i) 임의 타일 B와 교환(§5.2 스왑 유효성 적용)하거나 (ii) 빈 유효 칸(포탑 장착, 성 보수 포함)에 놓는다. **처음 집는 A로 Fairy(`F`) 타일은 고를 수 없다**(Fairy House와 다른 타일은 됨. B로 Fairy를 고르는 것은 됨) ✅. Fairy는 사용 후 소멸한다. Fairy House는 하루 1회이며 매일 충전된다 |

- 상자와 TNT는 제거로 연쇄를 일으킬 수 있다. 그 연쇄에서도 콤보와 매치-4 보너스(§7)가 적용된다.
- 휴식일에는 상자를 열 수 없다.

### 5.8 밤의 개입

- 밤에 가능한 행동은 대포 방향 전환과 요정 사용뿐이다. 둘 다 드물고 영향이 작으므로, RL 1단계에서는 **밤을 완전 자동**으로 처리해도 된다. ⚠️(선택 사항)

## 6. 매치와 병합 해소 ✅

### 6.1 줄 판정 (`dE`)

- 모든 칸을 행 우선으로 훑는다. 각 칸 T에서 오른쪽과 아래쪽으로 **같은 (종류, tier)** 가 연속되는 길이를 센다.
- 다음을 만나면 끊긴다: 빈칸, 이동 불가 타일, cannon slot 위 타일, 사용 중인 요정 타일.
- 길이 ≥ 3이면 매치 줄이다.
- 대각선 매치는 없다.

### 6.2 그룹

- 타일을 공유하는 줄들은 **하나의 그룹**으로 합쳐진다. L, T, + 모양이나 긴 줄이 여기에 해당한다.
- 그룹 크기 n은 그룹에 속한 서로 다른 타일 수다.
- 그룹 전체는 **정확히 1개 타일(tier+1)** 로 합쳐진다. n이 크다고 tier가 더 오르지는 않는다. n은 보너스 스왑(§7.1)에만 영향을 준다.
  - 예: Stone 3, 4, 5개 → Arrow tower T1 1개. T1 Arrow tower 3개 → Bronze 1개. 상자 T1 3개 → Bronze 상자.

### 6.3 결과 위치(join tile) 선택

1. 기본: 줄 안에서 `movedTime`(마지막으로 움직인 시각)이 가장 큰 타일이다. 동률이면 스캔 순서상 먼저인 타일이다(가로줄은 왼쪽, 세로줄은 위쪽).
2. 스왑 직후의 첫 판정에 한해, **스왑한 두 타일 중 하나가 줄에 있으면 그 타일**이다.
3. 줄의 타일 하나가 이미 먼저 발견된 그룹에 속해 있으면, 그 그룹의 join tile을 따른다(그룹 병합).

**시각(`movedTime`) 계산 규칙**

원본은 시각을 1/60초 프레임 번호로 기록한다. 순서가 결과에 영향을 주므로, 원본 사실과 구현 관례를 구분해 적는다.

원본 사실 ✅:

- 스왑: B = t, A = t+1 (t는 그 프레임 번호).
- 플레이어 입력은 프레임 앞부분에서, 해소 종료는 뒷부분에서 처리된다. 그래서 행동이 일어나는 프레임은 항상 직전의 모든 움직임보다 뒤다. 행동으로 움직인 타일의 시각은 그 전의 모든 시각보다 크다.
- 해소 단계 k에서 제거·낙하·생성되는 타일은 모두 같은 프레임 F_k를 받는다.
- 합체로 업그레이드되는 타일은 F_k + D를 받는다(D ≥ 1, 아래 식).
- 다음 단계의 제거는 이번 단계의 합체·낙하 애니메이션이 모두 끝나고(상태 1 종료) 점멸(상태 2)을 거친 뒤에 일어난다. 따라서 F_{k+1}은 이번 단계의 모든 업그레이드 시각보다 크다.

구현 관례:

- 순서만 보존하면 되므로 F_{k+1} = F_k + (충분히 큰 값)으로 둔다. 원본의 절대 프레임 수와는 다르다. 이 관례의 결과는 원본 대조로 검증했다(부록 C).

D 계산 ✅:
- 합체로 업그레이드된 타일은 F_k + D를 받는다. **D = 합쳐지는 타일 중 첫 번째가 결과 타일에 도착하는 프레임 수**이며, 아래 원본 애니메이션 식으로 계산한다.
  - 시작 위치: 모든 타일은 이번 단계 전의 칸 좌표((x−1)·48, (y−1)·48)에 있다. 결과 타일의 목표는 중력 적용 후의 칸이다.
  - 매 프레임, 타일 생성 순서(원본 타일 목록 순서)대로 다음을 적용한다. 결과 타일이 같은 프레임에서 합쳐지는 타일보다 먼저 처리되는지에 따라 도착 프레임이 1 달라질 수 있으므로, 이 순서도 그대로 따른다.
    - 결과 타일이 목표보다 위에 있으면 y를 2.88만큼 목표 쪽으로 이동한다(`moveto`, 넘어가지 않음).
    - 합쳐지는 타일은 결과 타일의 현재 위치를 쫓는다.
      - x는 0.1·|dx| + 0.96만큼 이동한다.
      - y는 c·|dy| + 2.88만큼 이동한다. c는 결과 타일보다 아래에 있으면 0.045, 아니면 0.09다.
    - |dx| ≤ 1.44이고 |dy| ≤ 1.44가 되면 그 프레임에 합체가 완료된다.
  - 대표값(검증용): 가로 합체 16프레임, 세로 합체 중 결과 타일이 떨어지는 경우 7–8프레임, 세로 합체 중 결과 타일이 맨 아래라 떨어지지 않는 경우 10프레임.
  - 즉 **같은 단계에서 동시에 생긴 타일 중에서는, 가로로 합쳐진 쪽이 더 늦게 완성되어 "더 최근"이 된다.**
- 모루로 옮겨진 타일과 배치된 아이템은 그 시점의 새 시각을 받는다.
- 요정(Fairy) 교환: 원본은 교환한 바로 다음 프레임에 요정 타일을 치운다. 그래서 그때 떨어지는 새 타일의 시각은 교환 시각(교환된 두 타일 중 늦은 쪽)을 넘지 않는다. 🔁
- 시각이 같으면 스캔 순서상 먼저인 타일이다(원본과 동일).
- 이 규칙이 영향을 주는 경우는 같은 연쇄 단계에서 새로 생긴 타일 2개 이상이 다음 매치 줄에 함께 들어갈 때뿐이다.
  - 예: 새 화살탑 T1 두 개가 (1,5), (2,5)에 동시에 생기고, (3,5)의 기존 T1과 가로로 다시 매치되는 경우.
  - 세로줄 결과는 어느 타일이 선택되든 맨 아래 칸에 놓이므로(§6.4), 위치 차이는 가로줄에서만 생긴다.

### 6.4 해소 알고리즘

```
combo = 0
loop:
    groups = find_groups(board)            # §6.1–6.3
    if not groups: break
    for g in groups:
        bonus_swaps += big_match_bonus(g)  # §7.1 (join tile의 업그레이드 전 값 기준)
        combo += 1
    for tile in row_major_order(board):    # y=1..7, x=1..6
        if tile in some group and tile is not its join tile:
            remove_with_gravity(tile)      # §4.2: 위 타일 한 칸 하강, (x,1)에 생성
    for g in groups:
        g.join.tier += 1                   # 자원 → 방어물 T1, Fairy → Fairy House
        g.join.movedTime = now()
if combo >= 3: swaps += combo - 2          # §7.2
if swaps <= 0: → 밤 (단, 상자 열기 선택 가능, §5.0)
```

- join tile도 중력의 영향을 받는다. **세로줄 매치의 결과물은 결국 그 줄의 가장 아래 칸에 놓인다.** 위쪽 제거로는 안 움직이지만, 아래쪽 칸이 제거되면 한 칸씩 내려오기 때문이다.
- 게임 시작, 매일 아침, 상자 열기, TNT, 아이템 배치 뒤에도 같은 해소가 돌아간다.

## 7. 추가 스왑 ✅

### 7.1 큰 매치 (n ≥ 4)

보너스 = (n − 3) × v. v는 **업그레이드 전** join tile의 값이다(`merchantAndMatch4SwapsGet`).

| join tile | v |
|---|---|
| 자원(T0, Treasure 포함) | 1 |
| 방어물·모루·빙산 tier k | 3^k (T1 3, Bronze 9, Silver 27) |
| Chest T1 / T2 / T3 | 4 / 16 / 90 |
| Fairy | 9 |

휴식일에는 없다.

### 7.2 콤보(연쇄)

- 한 번의 행동이 일으킨 해소 전체(최초 매치 + 연쇄)에서 해소된 **그룹 수의 합을 c**라 한다. c ≥ 3이면 **+ (c − 2)** 스왑이다.
- 예: 동시 매치 2개 + 연쇄 1개 → c = 3 → +1.

### 7.3 상자 열기

| 상자 tier | 스왑 | 아이템 확률 = 1/2.9^(4−k) |
|---|---|---|
| T1 (Treasure 3개) | +2 | 4.1% |
| Bronze | +12 | 11.9% |
| Silver | +70 | 34.5% |
| Gold | **+380** | 100% |

- 여는 것은 무료다. 상자는 제거되어 중력, 생성, 연쇄가 일어난다. 아이템이 나오면 상자가 그 아이템으로 변할 수 있다(§8).
- 상자를 모아 한 번에 합치거나 여는 타이밍이 핵심 전략이다(📘 가이드: "은상자가 최적").

## 8. 상자 아이템 ✅ (V RNG)

아이템이 나오면 먼저 종류를 정한다.

- p_devil = 0.55 × 0.9^(지금까지 수락한 악마 거래 수)
- 확률 p_devil로 **악마의 거래**
- 나머지 (1 − p_devil)는 아래 6종에 균등 분배

| 아이템 | 효과 |
|---|---|
| TNT | 상자 → TNT 타일, 충전 U{1..3} |

### 8.1 악마의 거래 (Devil's deal)

제안은 아래 순서로 정한다.

1. 20%: **포탑 제안**. 조건은 포탑 슬롯(1 또는 6)이 비어 있는 것이다.
   - 50%: 보드의 무작위 Arrow tower를 빈 슬롯으로 옮기는 제안이다(보드에 Arrow tower가 없으면 성립하지 않음).
   - 50%: 인벤토리 분기다. 인벤토리는 항상 비어 있으므로 성립하지 않는다.
   - 성립하지 않으면 2로 넘어간다.
2. 아니면 20%: **대포 슬롯 제안**.
   - 후보: 열 1..6마다 아래(7행)에서 위로 올라가며 **슬롯이 아닌 첫 땅 칸**을 찾는다. 1행은 보지 않는다. 그 칸의 타일이 **자원, 대포, 지금 여는 상자** 중 하나면 후보이고, 아니면(다른 방어물·모루·빈칸 등) 그 열은 후보가 없다.
   - 후보가 있으면 U{1..후보 수}로 하나를 골라 그 칸을 cannon slot으로 바꾼다. 그 칸이 대포면 슬롯 위 대포로 유지하고, 아니면 타일을 제거한다(§4.2 0번 규칙대로 빈 슬롯이 남는다).
   - 후보가 없으면 3으로 넘어간다.
   - 슬롯의 대포는 재장전 ×0.7(표기상 "+30% 속도")이다.
3. 아니면 20%: **빙산 제안**. 빈 물 칸(First에서는 y=7)에 빙산 T U{1..3}을 놓는다.
4. 아니면: **방어물 제안**. {Arrow tower, Ballista, Cannon, Ice Wall, Chest, Anvil} 중 균등으로 하나를 고른다. tier는 1이고, 이전에 거래를 수락하거나 거절한 적이 있으면 2다. 놓을 칸은 악마가 고르며, 자원 또는 Fairy 타일을 덮어쓴다. 덮어쓸 때는 종류·등급만 바꾸므로 대포 방향이 자동 설정되지 않는다(§9.5).
   - 선택 식: score = U(88..100) / (y+3) / (같은 종류 이웃 수: 제안 종류 기준) × (같은 종류 이웃 수: 기존 타일 종류 기준). JS 규칙대로 0으로 나누면 +∞, ∞×0 = NaN(제외)이다. 최대 점수 칸을 고르고, 동률이면 행 우선 스캔에서 먼저인 칸이다. 기본값은 여는 중인 상자 칸이다.

가격 H:

- hearts > 1일 때만 난수 1개를 뽑는다(hearts ≤ 1이면 난수를 쓰지 않고 H = 0). 그 값이 0.5보다 크면 H = U{2..5} + min(수락 횟수, 4)이고, 단 hearts − 1을 넘지 않는다.
  - 원본 조건은 `V.floatGet() > .5 || rK || ap`다. 시뮬레이터는 rK = false, ap = false로 둔다(§14).
- 그 밖에는 H = 0이다. 원본에서는 광고 보기 조건이며, 웹(광고 없음) 버전에서는 15초 대기 후 수락된다. 시뮬레이터에서는 **무료 수락**이다(§14).

플레이어는 **수락(하트 −H) 또는 거절**할 수 있다.

- 수락하면 "수락 횟수"가 1 늘어난다(H = 0 포함). 수락 횟수는 p_devil과 이후 가격에 영향을 준다.
- 거절하면 "거절 횟수"가 1 늘어난다. 수락·거절 횟수는 이후 방어물 제안의 tier에 영향을 준다(4번 항목).

### 8.2 Shop 상세 ✅

제시 품목 3개를 V RNG로 생성한다. 골드 가격은 쓰지 않지만 **가격 추첨도 난수를 소비하므로 순서를 그대로 따라야 한다.**

1. 무료 품목 번호 i = U{1..3}을 먼저 뽑는다.
2. 품목 s = 1, 2, 3 순서로 다음을 한다. 각 품목은 **가격 U{3..20}(×10)을 먼저 뽑는다.**
   - s = 1: 방어물 종류를 뽑는다(`dA`). 18종 목록에서 U{1..18}로 뽑아 {Anvil, Ballista, Arrow tower, Cannon, Chest, Ice Wall}이 나올 때까지 다시 뽑는다. T1.
   - s = 2: 하트 +U{2..4}. 최대 36을 넘는 만큼은 줄인다. 그래서 0 이하가 되면(하트가 가득 참) 1번과 다른 종류를 같은 방식으로 다시 뽑아 T2로 바꾼다.
   - s = 3: r = U{1..4}를 뽑는다.
     - 1: 모루, 등급 U{2..3}
     - 2: Fairy. 이어서 U{1..20}이 1이면 Fairy House
     - 3: 보드 안의 빈 물 칸 목록이 비어 있지 않으면 그중 하나를 뽑고(`$T`, 난수 1개), 빙산 등급 U{1..2}. 목록이 비었으면 난수 없이 TNT 폭파
     - 4: TNT 폭파 1회

무료 품목을 받으면:

- 타일 품목: 플레이어가 놓을 칸을 고른다. 조건은 그 종류가 들어갈 수 있는 칸이다.
  - 땅 칸이면 된다. 빙산은 보드 안의 물 칸이다.
  - Arrow tower는 포탑 조건(§5.5)을 만족하면 포탑 슬롯도 된다.
  - **그 칸의 기존 타일을 덮어쓴다.** 열고 있는 상자 칸도 된다. 이후 매치 해소를 한다.
  - 덮어쓸 때는 종류·등급만 바꾸므로(`kindSet2`) 대포 방향이 자동 설정되지 않는다(§9.5).
- 하트: 즉시 더한다.
- TNT 폭파: TNT 타일 없이 TNT 메뉴(§5.7: 전부 폭파 / 하나 폭파)를 1회 실행한다.

## 9. 밤(공격) 단계 ✅

### 9.1 웨이브 생성 (`m7`, 적 RNG M)

- First 레벨의 드래곤 수 n:
  - 기본: n = ceil(2.6·d) + 2 − 1
  - d > 50: n = ceil(0.4·(ceil(2.6d)+2)) − 10 + 13·(d−50) − 1
- 분산 폭 S = 48·(d/14 + 1) px. d > 50이면 ceil(0.8·S).
- 드래곤 i (1..n):
  - 열 c_i ~ U{1..6}
  - pixelX = (c−0.5)·48 + (U[0,1) − 0.5) × J
  - J = 4.800000000000001(Green, 범위 약 ±2.4), 2.4000000000000004(Red, 51일 이후, 범위 약 ±1.2). 상수는 원본 부동소수 값 그대로 쓴다 ✅
  - pixelY = 432 + (i/n)·S
  - 모두 같은 프레임에 화면 아래(y ≥ 10)에서 생성된다.
- 보스 날(d = 10, 20, 30, 40, 50)은 **마더 드래곤 1마리만** 나온다(§10).
- 일반 드래곤의 열은 밤이 시작될 때 정해진다. **낮 동안에는 알 수 없다.** 보스의 열은 그날 아침에 공개된다.

### 9.3 이동

- 매 프레임 `pixelY −= v_eff`로 위로 직진한다.
  - v_eff = 기본 속도 × 얼음 계수 × 스폰 가속(마더와 아기 드래곤만 생성 후 50프레임 동안 0→1 선형)
- 격자 위치:
  - gridX = clamp(floor(pixelX/48)+1, 1, 6)
  - gridY = floor(pixelY/48)+1
- 가로 이동은 넉백과 아기 드래곤의 흩어짐으로만 생긴다. pixelX < 0이면 매 프레임 +0.5, pixelX > 288이면 −0.5로 되돌린다.
- **드래곤은 타워를 공격하거나 막히지 않는다.** 모든 타일 위를 날아서 지나간다.

### 9.4 얼음 감속

- 드래곤이 있는 칸 (gridX, gridY)에 Ice Wall(또는 빙산)이 있고, 칸 안 위치 f = frac(pixelY/48)가 창 안에 있으면 감속된다.
  - Ice Wall: 0.1 < f < 0.6
  - 빙산: 0.5 < f < 1.0
- 이때 속도 계수는 **1 − (0.42 + 0.12k)** 다. k는 tier.

| tier | 계수 |
|---|---|
| T1 | ×0.46 |
| Bronze | ×0.34 |
| Silver | ×0.22 |
| Gold | ×0.10 |

- 한 칸(48px) 가운데 24px 구간에서만 감속된다.

### 9.5 타워 ✅

**사격 규칙** (`update6`, 밤에만):

- 매 프레임 `cooldown ≤ 0`이면 유효 대상 중 우선순위가 가장 높은 대상에게 쏘고 `cooldown = R / 2.4^(k−1)`로 설정한다. 슬롯 위 대포는 ×0.7이다.
- 그 뒤 **매 프레임 `cooldown −= 1`** 이다. 대상이 없어도 계속 감소하므로, 대상이 들어오는 즉시 쏜다.
- 따라서 실제 발사 주기는 **ceil(R/2.4^(k−1)) 프레임**이다.
- 매일 밤 시작 시 cooldown은 0이다.

- 대상 조건: 살아 있고 gridY < 10일 것. 화면 아래 대기 중인 드래곤은 대상이 아니다.

**대상 우선순위:**

- Arrow: 점수 = 288 − (|타워 중심x − ex| + |타워 중심y − ey|).
  - 날아가는 화살 수 × 3 ≥ 남은 HP이면 ×0.1
  - 날아가는 화살이 없고 이미 피해를 입은 상태이면 ×2
  - 최댓값을 고르고, 동률이면 적 목록(생성 순서)에서 먼저인 쪽이다.
- Ballista: 48 / (|타워 y − ey| + 48). 세로로 가장 가까운 대상이다.
- Cannon: (48 + B) / (|cx − ex| + 48).
  - cx = 타워 중심 ± 26.4(바라보는 쪽)
  - B = 3168 (적이 바라보는 쪽에 있거나 같은 열일 때), 아니면 0
  - 결과적으로 바라보는 쪽을 강하게 우선한다. 바라보는 쪽에 적이 없으면 반대쪽도 쏜다.
  - 방향 필드는 두 개다.
    - 선호 방향 `flippedPreferred`: 탭으로 바꾸며, 대상 우선순위에 쓰인다.
    - 현재 방향 `flipped`: 쏠 때 대상 쪽으로 바뀌고, 매일 아침 선호 방향으로 초기화된다. 포탄 출발 위치에 쓰인다.
  - 선호 방향이 정해지는 경로 ✅:
    - 매치·모루 업그레이드(`upgrade`): 결과 대포가 x ≥ 5면 왼쪽으로 설정된다. 아니면 기존 값을 유지한다(Iron에서 막 생긴 대포는 오른쪽).
    - Shop 배치·악마 거래(`kindSet2`로 기존 타일을 덮어씀): 자동 설정이 없다. 덮어쓴 타일의 기존 값이 남는다(일반 자원이었다면 오른쪽).
    - 이동·교환: 유지된다.

**투사체** (속도 3.84 px/frame):

- 출발 위치 ✅: 타워 중심 (px+24, py+24).
  - 성 포탑(격자 y ≤ 0)은 y를 3 더 뺀다. 예: (1,0) 포탑은 (24, −27).
  - 대포는 현재 방향 쪽으로 x ±12, y −1.

- Arrow: 매 프레임 대상을 향해 추적한다. 명중 시 3 피해. 대상이 먼저 죽으면 화살 위치 9px 안의 다른 적으로 바꾸고, 없으면 소멸한다.
- Ballista: 추적한다. 명중 시 6 피해. 대상이 죽으면 같은 열의 같은 방향(위/아래)에서 살아 있는 첫 적으로 바꾸고, 없으면 원래 대상 위치까지 날아가 소멸한다.
- Cannon: 예측 지점을 조준하며 추적하지 않는다.
  - 예측 y = 목표 y − |dx|/3.84 × 목표의 현재 속도
  - 발사 위치는 바라보는 쪽으로 ±12px이다.
  - 도착(5×5 겹침) 시 적 목록을 생성 순서대로 보고, 포탄의 2×2 영역과 겹치는 **첫 적 1마리**에게 6 피해를 준다.
    - 이 순회는 **죽은 적(목록에 남은 동안)을 거르지 않는다.** 먼저 겹친 적이 죽은 적이면 피해 없이 순회가 끝나고 폭발한다.
  - 이어서 폭발(`explodedTime` 1부터 시작)이 일어난다. `explodedTime == 5`가 되는 프레임에 한 번, 15×15 영역과 겹치는 모든 적(죽은 적 포함)을 **x, y 모두 0.3·w**만큼 넉백한다. **범위 피해는 없다.**

**명중과 넉백:**

- 삼각함수(`atan2`, `cos`, `sin`)는 JS 엔진마다 마지막 비트가 다를 수 있다(V8, iOS JavaScriptCore 등). 즉 원본 게임도 플랫폼별로 10⁻¹⁶ 수준의 차이가 있다. 시뮬레이터는 V8 소스의 fdlibm 이식본을 쓴다(V8과 비트 일치율 99.8%). 결과에 영향을 준 사례는 대조에서 찾지 못했다.
- 충돌 판정은 사각형 겹침이고, 경계는 엄격 부등호다 ✅(`rectshit`): 두 사각형 (x1,y1,w1,h1), (x2,y2,w2,h2)는 x1 < x2+w2, y1 < y2+h2, x2 < x1+w1, y2 < y1+h1일 때 겹친다.
  - 적 사각형: (ex − s/3, ey − s/2, 0.66·s, s). 즉 오른쪽 끝은 ex − s/3 + 0.66s다.
  - 투사체 사각형: 중심 기준 2×2 (폭발 중에는 15×15).
- 피해를 받고 살아남으면 넉백된다: ex += cos θ·w, ey += sin θ·w/2 (θ = 투사체 진행 방향). 폭발 넉백(위)과 계수가 다르다.
  - 아래에서 쏜 공격은 드래곤을 **위(성 쪽)로 w/2px 밀어 올린다.**

### 9.6 성 도달과 피해

- pixelY < −48이 되면 성에 도달한 것이다(이 프레임을 0으로 둔다). 경과 프레임이 **15를 넘는 첫 프레임(16번째)**에 **hearts −1**(골드 드래곤은 0)이 되고, 드래곤은 제거된다 ✅.
- hearts ≤ 0이면 즉시 게임 오버다(§12).

### 9.7 밤 종료

- 살아 있는 드래곤, 죽는 중인 드래곤, 투사체가 **모두 0**이 되면 day += 1이 되고 §11로 넘어간다.
- 죽은 드래곤은 사망 프레임부터 경과 프레임이 **20을 넘는 첫 프레임(21번째)**에 목록에서 빠진다 ✅. 그 전까지는 목록에 남아 포탄 판정에 걸릴 수 있다(§9.5).
- **시체 크기 증가** 🔁: 원본의 드래곤 그리기 함수(`draw2`)는 처치된 드래곤(성 도달 제외)의 크기를 사망 후 20프레임 동안 그릴 때마다 0.3씩 키운다(22.8 → 28.8). 커진 시체가 포탄을 흡수하므로 대포가 헛방을 치는 빈도가 늘어난다. 1프레임에 로직 1회·그리기 1회(60fps) 기준으로 반영한다. 기기가 느려 한 번 그릴 때 로직이 여러 번 돌면 원본에서도 값이 달라진다.

### 9.8 프레임 내 처리 순서

1. 포탑(x=1..6), 이어서 보드 타일이 생성 순서대로 사격을 판정한다.
2. 드래곤을 생성 순서대로 이동한다.
3. 투사체를 생성 순서대로 이동하고 명중을 처리한다.
4. 밤 종료를 검사한다.

## 11. 하루 전환 절차 ✅

밤이 끝나면 다음 순서로 진행한다.

1. `day += 1`
2. 업적 판정: day ∈ {11, 21, 31, 41, 51}이면 업적 수 A = min(5, floor((day−1)/10)).
3. day가 보스 날이면 보스 열을 정한다(적 RNG).
4. 모든 타워 cooldown = 0, Fairy House 충전.
5. `swaps = 5`, 빈칸 보충(§4.3), 자동 매치 해소.
6. day ∈ {11, 21, 31, …}이고 휴식일을 아직 쓰지 않았으면 휴식일을 제안한다(§13).

## 12. 게임 오버와 점수 ✅

- hearts는 시작 **5(고정)**, 최대 **36**이다.
- 밤에 hearts가 0이 되면 **즉시 게임 오버**다. **부활(수리)은 없다**(👤 결정).
  - 참고로 원본에는 게임당 1회 "수리"가 있다. 광고를 보거나 골드 100을 내면 하트를 5로 되돌리고 그날 밤 남은 드래곤을 없앤다. 시뮬레이터에서는 쓰지 않는다.
- **점수 = d + 1000·A**
  - d = 게임이 끝난 날
  - A = min(5, floor((d−1)/10)) = 넘긴 보스 수
  - 예: 64일차에 사망하면 64 + 5000 = 5064점.

## 13. 휴식일 (Day off) ✅

- **한 게임에 1회**, day 11/21/31… 아침에 "하루 쉬며 재배치할까요? 새 타일이 떨어지지 않습니다"를 제안한다.
- 수락하면 그날은 다음과 같다.
  - 보드 행동이 무제한·무료다(스왑 차감 없음).
  - **새 타일이 생성되지 않는다.** 제거된 자리는 열 위쪽의 구멍으로 남는다.
  - 매치 보너스와 콤보 보너스가 없다.
  - 상자 열기와 성 보수가 불가능하다.
  - 플레이어가 "Done"을 누르면 밤으로 넘어간다(밤은 정상 진행).
- 구멍은 다음 날 아침에 보충된다.
- RL 관점에서 추가 행동 "Done"과 이날의 무제한 행동 처리(스텝 상한)가 필요하다.

## 14. 온라인·과금·광고 요소 (👤 결정)

시뮬레이터는 항상 다음 상태를 가정한다.

- **골드 0, 인벤토리 비어 있음, 성 업그레이드 0, 비로그인(게스트).**

- **광고 = 웹(광고 없음) 버전 동작.** 코드의 web 플랫폼에서는 광고 대신 "Tower Swap has an app!" 화면이 15초 동안 뜬 뒤 보상이 지급된다(✅ 상태 120 → 24 → 보상 지급 `lx`). 따라서 광고 조건 보상은 **무료**다.

## 17. 시뮬레이터 구현 메모 (규칙에서 바로 따라 나오는 사항)

- **시뮬레이터의 결정 시점은 낮뿐이다**(밤 조작을 끈 단순화, §5.8). 한 RL 스텝은 낮의 행동 1개다. 밤은 환경 내부의 전이다(보드 → 하트 손실).
- 필요한 행동 유형:
  - 드래그: **42칸(7행 포함) × 4방향 = 168**. 7행 빙산의 이동·교환·버리기가 있으므로 7행도 출발점이 된다.
  - 칸 선택: 6열 × 8행(0행 성 줄 ~ 7행) = 48칸. 평소에는 탭(상자 열기, 대포 방향 전환, TNT, 요정 사용), 선택 창에서는 대상 선택(0행은 요정으로 포탑 장착·성 보수를 할 때 필요)
  - 아이템 프롬프트 응답: 악마 수락/거절, 상인 판매 칸(거절 불가), Shop 무료 품목 받기(+놓을 칸) 또는 거절, 지니 자원 종류, TNT 대상, 요정 대상, 휴식일 수락과 Done
  - 스왑 0일 때: 무료 행동(상자 열기 등) 또는 밤 시작
  - 무효 행동은 마스킹한다(§5.2–5.3의 유효성 규칙).
- 관측에 필요한 상태: 보드 7×6 (종류, tier, TNT 충전, Fairy House 사용 여부, 대포 선호 방향), **지형(물·땅·cannon slot)을 타일 종류와 별도로**, 포탑 2개, hearts, 남은 스왑, day, 보스 열(보스 날), 휴식일 사용 여부, 악마 거래 수락·거절 횟수.
  - 슬롯 위 대포와 땅 위 대포는 이동·병합·보충·발사 주기가 모두 다르다.
  - 원본을 정확히 재현하는 데 필요한 내부 상태(RNG, `movedTime`, 타일 생성 순서)는 엔진이 갖고 있고, 에이전트 관측에 공개할지는 별도 설계다.
- 밤 시뮬레이션은 프레임 단위로 한다. 드래곤이 성까지 가는 거리가 약 480 + S px이므로, 감속이 없으면 (480 + S)/v ≈ 600–750프레임이고 얼음 감속 시 늘어난다. 드래곤은 최대 약 130(49일)~180+(60일)마리다. 학습 처리량을 위해 numba나 C++/Rust 구현을 권장한다.
- 재현성: 보드 RNG(V)와 적 RNG(M)를 분리한다(부록 A). 원본과 똑같이 맞추려면 RNG 소비 순서를 그대로 따라야 한다.
- 검증용 단위 테스트 예:
  - 1일차 드래곤 4마리, 9일차 25마리
  - Arrow T1 주기 55프레임, Silver 10프레임
  - 금상자 +380
  - 스톤 4개 매치 시 +1 스왑
  - T1 Arrow 4개 매치 시 +3 스왑
  - 세로 3매치 결과는 맨 아래 칸
  - 7행 빙산 쪽으로 땅 타일을 끌면 버리기, 슬롯 위 대포 제거 시 보충 없음
  - 마더 10일차 HP 97, 아기 10마리

## 부록 A. 난수 (✅)

- 난수 생성기는 xorshift32이며, 인스턴스는 3개다.
  - `V`: 보드 스폰, 상자 아이템
  - `M`: 적(enemyseed)
  - `H`: 연출
- 새 게임 시작 시 시드는 `Date.now()`에서 얻는다.

```js
next():  s ^= s << 13; s ^= s >>> 17; s ^= s << 5;   // JS int32 연산
         return s >>> 0                               // uint32
float(): next() / 2^32
int(a,b): a + next() % (b - a + 1)                    // b-a+1이 비정수일 수 있음(아기 흩어짐 프레임)
```

- 타일 종류 추출: int(1,18)로 아래 목록(1-indexed)에서 고르고, 자원이 아니면 다시 뽑는다.

  `[Anvil, Cannon slot, TNT, Iceberg, Fairy, Fairy House, Time Machine, You, Wood, Ballista, Stone, Arrow tower, Iron, Cannon, Treasure, Chest, Ice cube, Ice Wall]`

- 적 RNG 소비 지점:
  - 드래곤 생성자: float 1회(애니메이션 프레임)
  - Green/Red: 열 int(1,6) + x 지터 float (지터 폭은 Green 4.800000000000001, Red 2.4000000000000004)
  - 아기 드래곤: 위에 더해 각도 int(0,360), 흩어짐 int(5, 20+0.6d)
  - 보스 열: 그날 아침 int(1,6)

- 검증 보고서 `tower_swap_rules_audit.md`의 지적 12건과 구분 사항 5건을 원본 코드와 다시 대조했다. 모두 코드와 일치해 이번 판(1.1)에 반영했다. 보고서의 검사 26개도 모두 통과했다.
